### **The Definitive Blueprint for the ViP-C Framework (Final, Enriched-State Version)**

#### **I. Core Philosophy: "Hierarchical Finite-State Subgoaling"**

The ViP-C is a hierarchical policy that learns to approximate a classic Finite State Machine (FSM). Its core principles are:

1.  **Dynamic Planning:** The high-level Planner is not a one-shot system. It is a state-based policy that is re-queried whenever the task phase changes, allowing it to dynamically issue the correct command for the current context.
2.  **Rich State Conditioning:** The Planner's decisions are explicitly conditioned on a multi-phase `TaskPhase` enum. This forces the model to learn distinct sub-policies for reaching, grasping, transporting, and placing, eliminating the causal ambiguity that plagued its predecessor.
3.  **Grounded, Geometric Subgoals:** The communication from Planner to Controller is a spatial heatmap. This is an unambiguous, geometric instruction, grounding the high-level plan directly into the robot's visual space.

#### **II. High-Level Architecture & Data Flow**

The ViP-C is a single, end-to-end trainable `torch.nn.Module` composed of two distinct but interconnected components:

1.  **The Planner (The "Foreman"):** A state-aware, high-level policy. It analyzes the global context (`current_image`, `goal_image`, `task_phase`) and decides **what the next key objective is**. It runs periodically upon a change in task phase.
2.  **The Controller (The "Worker"):** A powerful, low-level diffusion policy. It receives a simple geometric objective from the Planner and, looking at the immediate surroundings (`observation_history`), generates the precise motor commands to achieve it. It runs at every control step.

The data flow is a state-driven dialogue:

1.  The **Planner** receives the current state (including the `TaskPhase`) and the goal, outputting a **Subgoal Affordance Heatmap**.
2.  A coordinate is extracted from this heatmap (`argmax`).
3.  The **Controller** receives this subgoal coordinate and the local observation history.
4.  The **Controller** executes a short horizon of low-level actions to drive the robot towards the subgoal.
5.  This loop repeats until a state transition is detected (e.g., the object is grasped), which triggers the Planner to issue a new subgoal.

#### **III. Component Deep Dive: The Planner ("Foreman")**

*   **Objective:** To learn a state-based policy that maps the current task phase and visual context to the correct next spatial subgoal.

III. Component Deep Dive: The Planner ("Foreman")
      Inputs (at decision time t):
      current_image: [B, 3, 224, 224] FloatTensor.
      goal_image: [B, 3, 224, 224] FloatTensor.
      task_phase_token: [B, 1, 768] FloatTensor. A learnable embedding representing the current phase of the task.
      Implementation: An nn.Embedding(5, 768) layer.
      The 5 Expert-Aligned States (TaskPhase Enum):
      0: APPROACHING_OBJECT
      1: EXECUTING_GRASP
      2: TRANSPORTING_OBJECT_TO_GOAL
      3: PLACING_OBJECT
      4: RELEASING_AND_RETRACTIN

*   **Internal Architecture:** A Vision Transformer (ViT) based architecture.
    1.  **Shared ViT Backbone:** A frozen, pre-trained ViT (`google/siglip-base-patch16-224`) encodes `current_image` and `goal_image` into patch token sequences.
    2.  **Fusion Transformer:** A standard, trainable `nn.TransformerEncoder` fuses the information.
        *   **Data Flow:** The input sequence is a concatenation of three distinct token types, each with its own learnable type embedding: `[current_image_tokens, goal_image_tokens, task_phase_token]`.
        *   **Shape of input to Fusion Transformer:** `[B, 197 + 197 + 1, 768]`.
        *   **Learned Behavior:** This structure forces the Planner to learn a different mapping for each `task_phase_token`. For example, it will learn that when the phase is `STARTING`, the output heatmap must be on a pre-grasp location, but when the phase is `OBJECT_GRASPED`, the heatmap must be on the final goal.
    3.  **Heatmap Generation Head:** Transforms the contextualized visual tokens into a spatial affordance map.
        *   **Implementation:** A sequence of transposed convolutional layers (`nn.ConvTranspose2d`).
        *   **Data Flow:**
            a.  Take the contextualized patch tokens corresponding to the `current_image` from the Fusion Transformer's output: `[B, 196, 768]`.
            b.  Reshape them back into a spatial grid: `[B, 768, 14, 14]`.
            c.  Upsample this grid through transposed convolutions to a target size (e.g., `[B, 64, 56, 56]`).
            d.  A final `nn.Conv2d(64, 1, kernel_size=1)` produces the final single-channel heatmap.
*   **Output:**
    *   `predicted_heatmap`: `[B, 1, 56, 56]` FloatTensor. A spatial probability distribution over the next subgoal location.

#### **IV. Component Deep Dive: The Controller ("Worker")**

*   **Objective:** To be a robust, short-horizon, goal-conditioned policy that can reliably execute "go-to-coordinate" commands.
*   **Architectural Note:** The Controller's architecture remains identical to the previous blueprint. Its strength lies in its simplicity and focused task. The increased intelligence of the overall system is deliberately isolated within the Planner.
*   **Inputs (at every control step `t`):**
    1.  `observation_history`: Standard dictionary of recent sensor data (`image_primary`, `image_wrist`, `proprio`).
    2.  `subgoal_coordinate`: A `[B, 2]` FloatTensor representing the normalized `(x, y)` coordinate of the *current* subgoal.
    3.  `noisy_action_sequence`: `[B, H_a, D_action]` FloatTensor (for training).
    4.  `diffusion_timestep`: `[B]` LongTensor.
*   **Internal Architecture:** The proven **Grounded Action Decoder** from `EgoPlanner`.
    1.  **Real-Time Observation Encoders:** Trainable `ResNetEncoder` modules for vision and an MLP for proprioception.
    2.  **Subgoal Encoder:** A small MLP that projects the `[B, 2]` coordinate into a high-dimensional `subgoal_token`.
    3.  **Denoising Core (Diffusion Transformer):** `EgoPlannerBlock` architecture with AdaLN-Zero, conditioned on a unified context of tactical observation tokens and the `subgoal_token`.
*   **Output:**
    *   `predicted_noise`: `[B, H_a, D_action]` FloatTensor.

#### **V. The Hierarchical Control Loop (The State Machine Dialogue)**

This is the runtime logic that orchestrates the Foreman and Worker.

1.  **Initialization (`t=0`):**
    *   Robot starts. The system determines the state is `TaskPhase.STARTING`.
    *   The **Planner** runs, receiving this state. It predicts a heatmap with a peak at a safe *pre-grasp* location above the object.
    *   This peak's `(x, y)` coordinate becomes `current_subgoal`.

2.  **Controller Loop 1 (Reaching):**
    *   At every step, the **Controller** executes actions to drive the end-effector towards `current_subgoal`.
    *   The system continuously monitors for a state change. Once the end-effector is near the object, the state logic updates the phase to `TaskPhase.REACHING_FOR_OBJECT`.

3.  **Re-Planning Trigger 1 (Near Object):**
    *   The state has changed. The **Planner** runs again, now with `TaskPhase.REACHING_FOR_OBJECT`.
    *   It predicts a new heatmap, this time with a peak *precisely on* the object's grasp site for the final descent. This becomes the new `current_subgoal`.

4.  **Controller Loop 2 (Grasping):**
    *   The **Controller** now executes actions to descend and grasp.
    *   The system monitors for a successful grasp. When `is_grasped` flips to `True`, the state logic updates the phase to `TaskPhase.OBJECT_GRASPED`.

5.  **Re-Planning Trigger 2 (Object Grasped):**
    *   The state has changed. The **Planner** runs again, now with `TaskPhase.OBJECT_GRASPED`.
    *   It now knows it's holding the object, so it predicts a heatmap with a peak on the final goal location. This becomes the new `current_subgoal`.

6.  This cycle of **Act -> Monitor State -> Re-Plan** continues through `TRANSPORTING_OBJECT` and `POSITIONING_FOR_PLACE` until the task is complete. This is a true, reactive, closed-loop hierarchical system.

#### **VI. Training Strategy**

*   **Data Engineering (The Prerequisite):** The `ViPCDataset` is the most critical new component.
    *   **Labeling Process:** A script must be created to pre-process the expert trajectories. For every single timestep `t` in the data, this script must:
        1.  **Determine the Ground-Truth `TaskPhase`:** Use a set of rules based on `is_grasped`, `dist(ee, object)`, and `dist(ee, goal)` to assign one of the 5 phase labels.
        2.  **Determine the Ground-Truth Subgoal:** Based on the assigned phase, identify the expert's next keyframe coordinate (e.g., if phase is `STARTING`, the next keyframe is the pre-grasp pose).
        3.  **Project and Render:** Project the 3D world coordinate of that future keyframe into the 2D pixel space of the `current_image` at `t`. Create the `ground_truth_subgoal_heatmap` by rendering a 2D Gaussian centered at this pixel.

*   **Combined Loss:** The training objective is to minimize a weighted sum of the Planner's and Controller's losses.
    ```python
    loss = (lambda_planner * loss_planner) + (lambda_controller * loss_controller)
    ```
    *   `loss_planner`: Pixel-wise MSE loss between the `predicted_heatmap` and the `ground_truth_subgoal_heatmap`.
    *   `loss_controller`: The standard diffusion MSE loss.

*   **Training Step (`forward` pass):**
    1.  The **Planner** takes `current_image`, `goal_image`, and the **ground-truth `task_phase_token`** to produce `predicted_heatmap`. Compute `loss_planner`.
    2.  The **Controller** takes `observation_history` and the **ground-truth subgoal coordinate** (teacher-forced) as input.
    3.  The **Controller** produces `predicted_noise`. Compute `loss_controller`.
    4.  Combine losses and backpropagate. Gradients flow through both components, teaching the Planner which subgoals lead to easily executable actions.
