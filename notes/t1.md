### **The Definitive "Maiden Voyage" Plan: A Short Baseline Run**

**Goal:** To verify the complete, end-to-end functionality of the RL pipeline by running the "RL from Scratch" baseline for a small number of timesteps. This will confirm that the environment, reward wrapper, and PPO agent are all communicating correctly and that learning is possible.

---

#### **Phase 1: Configuration and Command**

**1. The Command:**
You will run the simPplest possible experiment: Reinforcement Learning from a random initialization, without any BC pre-training or OCTO divergence reward.

*   **Command to run:**
    ```bash
    python run_experiment.py --run_name "Baseline_Sanity_Check" --bc_model_path None --w_plausibility 0.0 --total_timesteps 10000
    ```

*   **Rationale for each argument:**
    *   `--run_name "Baseline_Sanity_Check"`: Gives this test run a clear, descriptive name.
    *   `--bc_model_path None`: **This is key.** It tells the script to skip all pre-training and start the PPO agent with random weights.
    *   `--w_plausibility 0.0`: **This is also key.** It disables the OCTO divergence reward, so we don't need to load the heavy OCTO model for this test. This isolates the test to just the core RL loop.
    *   `--total_timesteps 10000`: A small but significant number of steps. It's long enough to see if the agent can learn *something* and to ensure the training loop is stable, but short enough to complete in a few minutes.

---

#### **Phase 2: What to Watch For (The Checklist for Success)**

As the script runs, you should actively monitor the output for the following signs of a healthy pipeline. This is how you will "ensure all of them" are correct.

**1. ✅ Successful Initialization (The first ~30 seconds):**
*   **Log Message:** Look for `[INFO] Creating vectorized environment...` and `[INFO] Environment created`.
*   **Log Message:** Look for `[INFO] Auto-selected policy 'MultiInputPolicy'...` (or `MlpPolicy` if you changed the obs space). This confirms the environment's observation space is being correctly interpreted.
*   **Log Message:** Look for `[INFO] Initializing PPO agent...` and `[INFO] PPO agent ready`.
*   **Log Message:** Look for `[INFO] No BC model provided — starting RL from scratch.` This confirms you are correctly running the baseline.
*   **Absence of Errors:** The script should start without any crashes, `TypeError`, or `KeyError` messages.

**2. ✅ Stable Training Loop (The next ~5-10 minutes):**
*   **Stable Baselines3 Output:** You should see the PPO training table appear and start updating. It looks like this:

    ```
    ---------------------------------
    | rollout/           |          |
    |    ep_len_mean     | 250      |
    |    ep_rew_mean     | -2.45    |
    | time/              |          |
    |    fps             | 150      |
    |    iterations      | 1        |
    |    time_elapsed    | 13       |
    |    total_timesteps | 2048     |
    | train/             |          |
    |    loss            | 0.15     |
    ---------------------------------
    ```
*   **Key metrics to watch:**
    *   `fps` (Frames Per Second): Should be a stable, positive number. If it's very low (e.g., < 10), there might be a performance issue.
    *   `ep_len_mean`: The average episode length. For your environment, this will likely be `250` (your `max_episode_steps`), meaning the agent is not solving the task yet but is running until the time limit. This is normal at the start.
    *   `loss`: The PPO loss should be a number and should generally decrease over the first few updates.

**3. ✅ Evidence of Learning (The most important check):**
*   **The Litmus Test:** The single most important metric is `ep_rew_mean` (mean episode reward).
*   **What to look for:**
    *   Initially, the reward will be negative and small (e.g., `-2.5`) due to the action penalty.
    *   Over the 10,000 timesteps, you should see this value **start to trend upwards**. It doesn't need to become positive, but you must see an improvement. For example, it might go from `-2.5` -> `-2.1` -> `-1.8`.
    *   **This upward trend is the proof that your entire system is working.** It confirms that the agent is receiving observations, taking actions, getting meaningful rewards from your `RLRewardWrapper`, and updating its policy to get more of that reward.

**4. ✅ Correct Artifacts:**
*   After the run finishes, check your project directory.
*   You should have a new folder: `trained_models/Baseline_Sanity_Check/`.
*   Inside it, there should be at least one checkpoint file (e.g., `dgpo_policy_10000_steps.zip`) and a `final_policy.zip`.
*   You should also have a new folder `tensorboard_logs/` containing the logs for this run. You can run `tensorboard --logdir ./tensorboard_logs` to visualize the `ep_rew_mean` and confirm the upward trend.

---

### **Interpreting the Results**

*   **If all checks pass and `ep_rew_mean` trends upward:** **Congratulations.** Your entire RL pipeline is correct and functional. You have successfully validated the environment, the reward function, and the PPO integration. You can confidently proceed with the full-scale pre-training and fine-tuning experiments.
*   **If the script crashes:** The traceback will point to the specific integration bug (e.g., a shape mismatch between the reward wrapper and the PPO agent).
*   **If the script runs but `ep_rew_mean` is flat or goes down:** This is the most subtle issue. It suggests that while the code is running, the reward signal is not meaningful enough for the agent to learn from. This would be the time to double-check the logic inside your `RLRewardWrapper` (e.g., are the reward scales appropriate?).
