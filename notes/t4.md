### **The Plan: Designing an Excellent Checkpoint & Resume System**

The goal is to add the ability to resume training seamlessly, preserving not just the model weights but also the optimizer state, the number of timesteps completed, and all other internal states of the RL algorithm. `Stable-Baselines3` makes this very easy.

Here is the elegant logic we will implement.

#### **Step 1: Update the Command-Line Interface (CLI)**

**File to Edit: `run_experiment.py` (inside the `if __name__ == "__main__":` block)**

*   **Action:** We will add a new argument, `--resume_from`.
*   **Logic:** This argument will be mutually exclusive with `--bc_model_path`. A user can either *start* a new fine-tuning run from a BC model or *resume* an existing fine-tuning run, but not both at the same time. This prevents logical conflicts. We will add a check to enforce this.

    ```python
    # Inside the main argument parser
    parser.add_argument("--bc_model_path", type=str, default=None, help="Path to a .pth BC artifact to START a new run.")
    parser.add_argument("--resume_from", type=str, default=None, help="Path to a .zip SB3 checkpoint to RESUME a run.")

    # After parsing args = parser.parse_args()
    if args.bc_model_path and args.resume_from:
        raise ValueError("Cannot provide both --bc_model_path and --resume_from. Choose one.")
    ```

#### **Step 2: Update the `run_experiment` Function to Handle Resuming**

**File to Edit: `run_experiment.py` (the `run_experiment` function)**

*   **Action:** We will add a new block of logic right after the environment is created.
*   **Logic:** The new logic will check if the `resume_from` path was provided.
    *   **If `resume_from` is provided:**
        1.  We will log a message indicating that we are resuming.
        2.  We will call `PPO.load()`. This single function is incredibly powerful. It will load the model, the optimizer, the replay buffer, the timestep count, everything.
        3.  Crucially, we must pass our `custom_objects` (containing the `BCFeaturesExtractor` and `policy_kwargs`) to `PPO.load()` so it knows how to reconstruct our custom architecture.
        4.  We will set the agent's environment to the new `env` we just created.
    *   **If `resume_from` is NOT provided (the old path):**
        1.  The script will proceed as it does now: create a new agent, and then optionally load the BC weights into it.

This design is clean, explicit, and easy to understand.

#### **Step 3: Ensure `learn()` Resumes Correctly**

*   **Action:** We need to tell the `ppo_agent.learn()` method **not** to reset its internal timestep counter when we are resuming a run.
*   **Logic:** The `.learn()` method has a `reset_num_timesteps` argument. When resuming, we must set this to `False`.
