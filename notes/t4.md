#### **Phase 1: Foundational Data Engineering - The Dataset Enhancement Pipeline**

**Analysis:** This is the most critical phase. The success of the ViP-C Planner is entirely dependent on the quality and correctness of its supervisory signals. We will create a robust pipeline that enhances our existing expert datasets by adding two new, essential data modalities: the `task_phase` and the `ground_truth_subgoal_heatmap`. This pipeline will be deterministic and geometrically precise, forming the bedrock of the entire project.

**Execution Plan:**

1.  **Modify the Data Generation Process (The Source of Truth):**
    *   **File to Modify:** The script that generates your expert trajectories (likely containing the `ExpertDataset` class).
    *   **Objective:** To capture all necessary ground-truth information at the source, eliminating any need for post-hoc heuristics.
    *   **Actions:**
        1.  **Persist Expert State:** At every single timestep of an episode generation, record the `ScriptedExpert`'s internal state string (e.g., "MOVE_TO_GOAL"). Save this sequence of strings as a new modality.
        2.  **Persist Camera Parameters:** At every timestep, query the MuJoCo simulation for the active camera's full parameters (position, orientation/`xmat`, field-of-view). Save this sequence of parameters as another new modality.
        3.  **Output:** Your `ExpertDatasetWriter` will now save an "enhanced" LMDB file that contains not only `obs` and `actions`, but also `expert_states` and `camera_params` for every step.

2.  **New File: `utils/dataset_enhancer.py` (Replaces `subgoal_labeler.py`)**
    *   **Objective:** To create a script that reads an enhanced LMDB dataset and adds the final `task_phase` and `subgoal_heatmap` modalities. This is a one-time, offline process performed on the dataset before training.
    *   **Class: `DatasetEnhancer`**
        *   **`__init__(self, source_lmdb_path: str, dest_lmdb_path: str)`:** Initializes with source and destination database paths. This process creates a new, final dataset to ensure the original is untouched.
        *   **Method: `_map_expert_state_to_phase(self, expert_state: str) -> int`:** A simple, deterministic mapping function that implements our expert-aligned `TaskPhase` enum:
            *   `"MOVE_TO_PRE_GRASP"`, `"PREPARE_GRIPPER"`, `"DESCEND_TO_GRASP"` -> `0` (APPROACHING_OBJECT)
            *   `"GRASP"` -> `1` (EXECUTING_GRASP)
            *   And so on for all 5 phases.
        *   **Method: `_find_target_keyframe(self, episode_states: List[str], current_phase: int) -> int`:** Logic that, given the current phase, finds the index of the future keyframe that defines the subgoal. E.g., if `current_phase` is `APPROACHING_OBJECT`, this method finds the first timestep where the state becomes `GRASP`.
        *   **Method: `_project_world_to_pixel(...)`:** The same 3D-to-2D projection utility, but it will now take the specific camera parameters for the current timestep as an argument.
        *   **Method: `_generate_heatmap(...)`:** The same 2D Gaussian rendering utility.
        *   **Main Method: `enhance_dataset(self)`:**
            1.  Opens the source LMDB for reading and the destination LMDB for writing.
            2.  Iterates through every episode in the source dataset.
            3.  For each episode, it copies all original modalities (`image_primary`, `actions`, etc.) to the destination DB.
            4.  It loads the full `expert_states` and `camera_params` sequences for the episode.
            5.  It creates two new empty lists: `task_phases` and `subgoal_heatmaps`.
            6.  It iterates through every single timestep `t` of the episode:
                a.  Looks up the `expert_state` at `t`.
                b.  Calls `_map_expert_state_to_phase` to get the `current_phase` and appends it to `task_phases`.
                c.  Calls `_find_target_keyframe` to determine the subgoal timestep, `k`.
                d.  Retrieves the end-effector's 3D world coordinate at timestep `k`.
                e.  Retrieves the camera parameters at timestep `t`.
                f.  Projects the 3D coordinate to a 2D pixel coordinate using the correct camera params.
                g.  Generates the heatmap and appends it to `subgoal_heatmaps`.
            7.  After iterating through the episode, it writes the completed `task_phases` and `subgoal_heatmaps` lists as new, compressed modalities to the destination LMDB.
